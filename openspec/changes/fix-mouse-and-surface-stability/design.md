# Mouse and visible-surface stability

Native SDL window-relative mouse mode is requested by a real mouse click only in on-foot/helm contexts. Relative deltas drive the existing sensitivity/inversion path after button release. Pause, focus loss, dialogs and station/settings/journey panels disable capture; resuming by keyboard does not silently recapture it. Touch-synthesized mouse events do not acquire mouse mode. SDL flushes queued mouse motion on mode changes, so the real-input replay acquires mode before sending its look delta.

The DOM adapter requests Pointer Lock directly in a trusted mouse-down on the canvas, never from a touch gesture. A relative mousemove listener owns look only while that canvas holds the lock, avoiding double-counting pointermove/absolute deltas. Unsolicited loss pauses and clears input; intentional panel releases do not pause active station time. A cancelled/late request cannot capture over a menu. Browser refusal leaves the existing drag/look-pad/keyboard path usable. Native menus and browser controls retain a free pointer. Touch remains independent of pointer lock/fullscreen.

The causeway's support rectangles overlap at Y0; the powered bridge overlaps their edge at exactly Y0 too. Interior boxes/hull parts also duplicate faces. Render a box union by subtracting covered rectangles from each exposed face, with the earliest box owning coincident outer surfaces. Keep cylinders out of rectangular occlusion masks. Static interior/hull surfaces share one batch; the additive bridge clips its visible faces against the full base world. Collision/support boxes do not move. Road paint is a flat decal pass with polygon offset, not thin boxes competing with distant floor depth. No projection, near-plane or save-layout changes are needed.

Mesh clipping uses bounded reusable scratch buffers and runs at static build time (plus the small additive bridge). Native/WebAssembly geometry tests check unique coplanar faces, union area, contained/touching boxes and bridge joins. SDL lifecycle checks query real relative mode after button release, menus and focus interruption; desktop browser checks use genuine pointer lock and relative motion, including beyond the viewport, with existing touch/regression coverage retained.
